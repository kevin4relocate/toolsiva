# Toolsiva analytics and privacy operations

Last reviewed: 2026-11-15

## Ownership

- **GA4 Measurement ID:** `G-SM8H6H5D74`. The website's opt-in `/analyticsConsent.js` is the only intended owner of GA4 configuration, an explicit, one-per-document `page_view`, and `/analyticsEvents.js` controls fixed non-content interaction events.
- **GTM Container:** `GTM-TVGV8PTP`, also loaded only after consent. **Do not publish a Google tag or GA4 Event tag for the same GA4 property in this container**, or you may double-count events/pageviews. This must be verified inside the GTM account: source code alone cannot enforce GTM's remotely managed tags.
- **Cloudflare Web Analytics:** A separate privacy-first beacon managed by Cloudflare. This repository does **not** embed a beacon with a guessed token, because Cloudflare Automatic Setup may inject it at the edge and adding a manual copy would lead to double counting.
- **Cloudflare Edge Traffic Analytics:** Requests, bot/crawler requests, and visits here are not the same measurement as browser-driven Web Analytics or opt-in GA4 sessions.

## Google Consent Mode v2: basic, opt-in implementation

1. `/analyticsConsent.js` is loaded synchronously from the document head and queues `consent/default` with analytics and advertising denied.
2. With no saved choice or `denied`: the browser does not request `gtag.js` or `gtm.js`; explicit GA4 pageviews and tool events are suppressed.
3. On `granted`: queue `consent/update`, configure GA4 with `send_page_view: false`, inject each Google library once, then queue exactly one explicit `page_view` after the document title is ready.
4. Direct GA4 pageview URLs use only origin + pathname (not URL search/query parameters or hashes); external referrers are also reduced to origin + pathname.
5. Advertising consent stays denied even if analytics is granted. No tag should override those values.
6. When someone revokes previously granted consent, the page reloads to remove already-loaded third-party Google scripts. Local storage retains only the preference, not a user ID.

The cookie panel controls Google Analytics only. The Cloudflare Web Analytics beacon is separate and may still run according to Cloudflare dashboard configuration.

## Production verification checklist

1. Deploy the merged `main` commit. In browser DevTools **Network**, reject Google Analytics in a fresh browser/private window: there should be **no requests** to `googletagmanager.com/gtag/js`, `googletagmanager.com/gtm.js` or GA4 collection endpoints generated by Toolsiva.
2. Accept: there should be **one** `gtag.js?id=G-SM8H6H5D74` request and **one** `gtm.js?id=GTM-TVGV8PTP` request. The direct tag emits one `page_view` with a path-only `page_location`.
3. In **GTM Preview / Tag Assistant**, verify that the container has **no second Google tag / GA4 pageview / duplicate GA4 event** targeting `G-SM8H6H5D74`, and that custom tags respect consent. If a GA4 tag exists in GTM, disable it before using the combined setup.
4. In **GA4 DebugView and Realtime**, compare one browser visit and clicks with collected events. Test a URL with query parameters: no tool input or search term should appear in event parameters or URLs.
5. Revoke Analytics via footer **Cookie settings**: confirm the page reloads and Google requests stop on the new page.
6. Check Markdown Live Preview: saving is off by default, enabling it saves only on the device, and **Delete saved draft** removes previous content.
7. In **Cloudflare → Web Analytics → Manage site**, confirm **Automatic Setup** for `toolsiva.com`. On a real page, check the network for exactly one `beacon.min.js` and one `/cdn-cgi/rum` call. If absent, inspect Cloudflare script injection and rules. Do **not** add a manual beacon while Automatic Setup is enabled; no token is present in this repository.
8. Check that the origin does not set `Cache-Control: public, no-transform` on HTML. Cloudflare documents that `no-transform` prevents automatic beacon injection. Verify Cloudflare Web Analytics after deployment using **Last 30 days** and compare equivalent time windows.
9. Inspect GA4 Realtime, Cloudflare Web Analytics and Cloudflare Edge Analytics separately. GA4 is opt-in, so its totals will naturally be lower than Cloudflare's browser/edge analytics.

## CI guarantees and limitations

`npm run analytics:verify` checks generated HTML to ensure all pages include exactly one local consent bootstrap and no statically embedded Google/Cloudflare beacon script. `npm run test:phase3` verifies opt-in behavior and URL redaction in isolated browser-like fixtures.

Automated tests cannot see the current remote GTM container's tags, the actual Cloudflare Managed Site setting, deployment status, real network blocking by extensions, or visitors' browser configuration. These must be verified in production.
