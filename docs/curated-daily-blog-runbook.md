# Toolsiva Phase 8 — 30 curated articles and scheduled illustrated publishing

Planned dates: **November 16 to December 15, 2026**, one article per Vietnam calendar day. Preferred time: **09:00 Asia/Ho_Chi_Minh** (GitHub Actions cron `0 2 * * *`). GitHub schedules may run late; this is not an exact delivery SLA.

## Editorial model

- The 30 *prewritten* Markdown articles live in `src/content/blog/` and are committed to this PR as **`draft: true`**. No article is public merely because the PR was merged.
- One schedule, `src/data/curatedGuideSchedule.json`, fixes the order, subject, link, date, original image file and descriptive alt/caption for every article.
- The manual AI-writing workflow `.github/workflows/daily-blog.yml` remains **draft/PR review only**. It never auto-publishes an arbitrary model-generated article.
- The new independent `.github/workflows/publish-curated-guides.yml` does not call an AI service. It only publishes prewritten articles that were included in the merged editorial queue and marked `curatedSeries: true`.
- The editorial quality, originality and worked examples should be reviewed in the PR before merging. Passing build and content checks does not certify every assertion or guarantee AdSense approval.

## One per day, without double posting

At 02:00 UTC each day, GitHub Actions checks out `main`, generates the static illustrations, and calls `npm run blog:release`.

The release script:
1. Checks the current time in `Asia/Ho_Chi_Minh` and refuses to publish before 09:00 Vietnam time.
2. Finds the earliest scheduled draft with date at or before the current date.
3. Verifies the locked slug, primary tool, image source, alt text, caption and `curatedSeries` flag.
4. Refuses a second release when a curated post has already been published that day.
5. Changes only that article's `draft` field and its actual published/updated dates.
6. Requires the illustration to exist and runs full validation/build/SEO/AdSense static checks before pushing to main.
7. Pushes the one changed Markdown file to `main` so the enabled Cloudflare Git integration can deploy.

If a day is missed, the next successful run publishes **one** oldest eligible article rather than dumping the backlog. It does not automatically backdate a newly published article. The series will finish later than December 15 if runs are missed.

If branch protection prevents the bot from pushing, GitHub Actions will fail rather than bypass branch rules. Review the workflow logs and GitHub repository Actions permissions; do not disable protection casually.

**Check Cloudflare deployment after the first scheduled publication.** Automated GitHub commits may interact differently with GitHub and external deployment integrations than a manual merge, and only a production check confirms the article is actually live.

## Each article has an original SEO image

- 30 dedicated SVG diagrams are generated by `scripts/generate-guide-images.mjs` from the canonical schedule data.
- One additional SVG diagram illustrates the pre-existing Markdown Live Preview guide.
- Build, local dev and blog validation generate the assets into `public/blog/illustrations/`. They are not separately stored as 31 hand-maintained files; assets are deterministic from the source and included in the Cloudflare build.
- Each published article has a descriptive filename, unique alternative text and visible `<figcaption>` under an accessible `<figure>`, with explicit 1200×630 dimensions.
- BlogPosting JSON-LD includes a URL to the relevant illustration. Google Search can crawl SVG images, but SVG is not consistently supported as an Open Graph preview by social networks; this release retains the site's existing raster social fallback.
- The schema blocks publishing a guide without an image, alt text and caption. Draft-only AI content can add those during editorial review.

## Quality and priority

The first posts target search-visible tasks including Age Calculator, Proportion Calculator, Tip Calculator, Random Text Generator, Morse Code Translator and List to Text. Seven high-impression tool pages receive on-page worked examples and intent-focused titles. A prior misleading Age Calculator claim about month/day output has been corrected to match the actual completed-years engine.

Topics are varied across calculator, text, developer, QR, security and converter categories. Each contains task-specific worked examples, input assumptions and meaningful limitations. Content quality is still assessed by people, not inferred from word count or traffic metrics.
